# Security reporting

Do not disclose vulnerabilities, working exploits, credentials or private user data in public issues.

Use [GitHub private vulnerability reporting](https://github.com/mrcholer/ludicord/security/advisories/new) when enabled. If that option is unavailable, open a public issue asking the maintainer for a private reporting channel **without including vulnerability details**.

Provide affected package versions, impact, a minimal sanitized reproduction and any workaround through the private channel. Never submit live secrets. If a secret was exposed, revoke or rotate it through its issuer immediately.

See the [application security guide](docs/security.md) for configuration. No fixed response-time or historical-version maintenance guarantee is currently stated.
